Instructor release and assessment guide

This public guide contains assessment criteria and facilitation advice, not hidden answer keys. Keep summative questions, solutions, and student records in a separate private repository; public Git history is not a safe place for them.

Before teaching: pilot one full learner setup; verify the selected model's license, revision and memory requirement; vet external reading links; recheck certification editions; retain an independent held-out assessment; and adapt pacing after the entry diagnostic. Reserve four flexible weeks for support and interviews.

Each week: retrieve earlier knowledge, demonstrate a small worked example, guide a variation, remove one scaffold, require an independent change, and ask the student to explain a failure. Offer text alternatives and avoid grading based on paid hardware/API access.

Each module's three public reflection questions are formative, not a secure exam. Create fresh summative variants privately. Assess implementation understanding through an unseen small modification and a short explanation, with assistive accommodations as needed. AI assistance is permitted with disclosure, but the student must own and explain the work.

Core automated checks validate deterministic behavior, local links, dataset accounting, role filters, notebook syntax, and generated-file freshness. The classical-ML job exercises real pandas/scikit-learn. Live LLM quality, embedding retrieval, fine-tuning, provider adapters, and cloud deployment require separately recorded runs. Do not mark these passed from fixtures.

Publish the course only after reviewing the draft PR. The initial release is a pilot, not a production security assurance or full certification preparation claim. The current root Pages setup is intentionally preserved. Merge only after checks and a learner navigation review. Revert the course commit to roll back; never force-push over student-facing history.
