Start here

You are BrewByte Coffee's junior technology analyst. BrewByte is fictional. Its customers, staff roles, transactions, support tickets, policies, and security events are synthetic educational data.

Plan 12–15 hours each week: 3 hours of lesson/resource study, 6–8 hours of practice, and 3–4 hours of evaluation, explanation, and documentation. Twelve four-week modules occupy 48 weeks; use four additional weeks for remediation and career work. No paid API is necessary for the core pathway. Existing hardware/internet are assumed. Free cloud/notebook allowances can change.

First session

  • Open Module 1 in the Academy. Complete the file/folder and numeracy warm-up before using tools.
  • Create a personal GitHub learning repository. Use the web editor initially; learn local Git in Module 2.
  • Install a supported Python 3.11/3.12 and VS Code, or use an interactive Colab notebook. Start with the standard-library labs.
  • Download or clone this repository so relative data paths work. Run a starter from the repository root: python ai-academy/modules/02/starter.py. The downloadable notebooks explain their setup in their first cells.
  • Create your own submissions/ directory outside this public teaching repository. Do not upload personal data or credentials.

What counts as completion

Read the lesson, run the worked example, vary an input, complete the independent challenge, and explain the result. Submit a README with the business problem, execution steps, evidence/metrics, security decisions, failures, and AI-assistance disclosure. Commit your own work to your own repository. Completing reading checkboxes is not evidence of competence.

Scoring: behavior 35%, evaluation evidence 25%, security/privacy 20%, reproducibility 10%, explanation/independent modification 10%. Target 80/100 plus mandatory controls. An unresolved credential exposure, seeded permission bypass, or fabricated metric requires repair. These are course thresholds, not vendor exam passing scores.

Real models versus fixtures

The default fixture is deterministic and works offline. It proves that code handles the supplied contract, not that an LLM generates correct answers or resists attacks. For Modules 1 and 7–10, collect genuine model outputs through the documented local-model or supervised notebook route. Record model/revision, settings, date, hardware, and limitations. No subscription is required; a suitable small local model or interactive free notebook may be used subject to availability. If hardware/access prevents execution, request an instructor session and label observed versus personally executed evidence.

Never describe fixture results as real-model performance, lexical search as embedding search, or local containers as a cloud deployment. Never treat a model's declared confidence as calibrated probability. All model outputs remain untrusted.

Accessibility and safe practice

All essential lessons are readable as Markdown as well as HTML. Pages use semantic headings and keyboard-accessible links, with no required animation. No student sign-in, progress tracking, or telemetry is implemented. Save your own evidence. Labs use only synthetic data and authorized local targets. Do not perform lab actions on workplace networks or real accounts.
