Module 03 · Week 1: Represent data and inspect sources

BrewByte assignment: Process an instructor-provided, seeded dataset of 2,000 fictional tickets with duplicates, missing fields, inconsistent dates, invalid categories, and synthetic identifiers. Produce a reusable cleaning script, data dictionary, lineage record, SQLite queries, and a concise exploratory report.

Learn the concept

A table has rows and columns; a NumPy array has a shape and usually one element type. A dataframe adds column labels and mixed column types. Before cleaning, inspect the source, schema, units, and row counts. A missing value is information about data collection, not simply a nuisance to erase.

Worked business example

BrewByte daily sales use units sold and unit price. A negative price or a date outside the collection period needs investigation. An order identifier should remain text so formatting is preserved.

Guided practice

Read this week's assigned resource sections about Percentages, elementary algebra, arrays/shapes, vectors, basic tables; load CSV/JSON. Spend about three hours on reading, small examples, and explaining the vocabulary in your own words. You are not expected to complete every linked course this week.

Open the guided notebook or starter script. The notebook names the dependency and execution requirements. Run the relevant worked example and inspect its inputs and outputs. For Module 1, begin with a manual prompt comparison; coding is introduced in Module 2.

Profile sales and dirty tickets. Write a data dictionary with units, allowed values, null rules, and source. Count rows before changing anything and inspect five representative problems.

Change one input or condition, predict the result, then run or observe it. Preserve a failing case before repairing it. Complete the task in your own learning repository rather than modifying the public teaching source.

Security boundary

Threats include accidental identifier disclosure, silent data corruption, and contaminated sources. Preserve an immutable source copy, validate schema and ranges, document provenance and transformation decisions, and limit exports. A hash establishes consistency relative to a trusted reference, not source trustworthiness or privacy. Explain why identifier removal alone may leave re-identification risk.

Submit evidence

Data dictionary and source profile. Include commands or procedure, relevant outputs, one failed case, your interpretation, and AI-assistance disclosure. Use synthetic data only. Clearly distinguish personally executed work, observed instructor demonstrations, and pending exercises.

Check your understanding

  • Which assumption in represent data and inspect sources could make your BrewByte result misleading?
  • What fails if the input is malformed, unauthorized, or missing?
  • What evidence would convince a reviewer that your change works on an unseen case?

These public questions are formative. Explain your reasoning; they are not hidden certification questions.
