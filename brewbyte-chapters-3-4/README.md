This is an additive website package. Upload this entire **new** folder without replacing the current homepage or any existing lesson folder. The site works independently of the earlier Academy and Connection Basics packages.

## Upload to GitHub

1. Extract `BrewByte_Chapters_3_4_Website_Addition.zip` on your computer.
2. In your chosen repository, open **Add file → Upload files** and upload the complete `brewbyte-chapters-3-4` folder, including `assets` and all code files. Keep the folder structure intact.
3. Commit the new files using your usual review process. If a folder with this name already exists, choose a different new folder name instead of replacing it.
4. After your existing GitHub Pages process publishes the new files, open the new folder’s `index.html`. Share that direct link in Blackboard. Do not replace the repository’s root `index.html`.

For the previously identified repository, the expected path after your upload is:
`https://jdmc-services.github.io/brewbyte-risk-management-lab/brewbyte-chapters-3-4/index.html`

That is an expected future path, not a claim that the page is already published. This task does not upload, merge or publish the repository. No existing tracked files were modified.

## What students receive

- Seven original missions covering Internet technologies, browser use, ISP selection, cybersecurity and responsible AI assistance.
- A shorter `basics.html` entry covering upload/download, one calculation, TCP/IP and optional Windows/Linux checks.
- Searchable original terminology, examples and flashcards.
- Original questions, fictional ISP offers, business decisions, synthetic messages and logs.
- Five original SVG explanations: TCP/IP/TLS, upload/download, browser storage, identity/access/accounting, and network zones.
- Three optional, click-to-load YouTube videos placed before the related activity.
- Human decision reflections, browser-local progress, text/JSON export and print styling.

The longer pathway may span several sessions. Start beginners with Connection Basics, and keep glossary extensions and videos optional. Every activity remains usable without a video or external AI tool.

Start/end parameters suggest a focused segment; the direct fallback link may allow viewing the full source. A follow-up explanation and viewing question accompany each clip.

Use a hosted page with a normal web origin for embedding, preferably your HTTPS GitHub Pages site. Local `file://` viewing may fail YouTube’s origin/referrer checks; use the direct YouTube fallback if necessary. Never disable a browser security warning to play a video.

## Operation and limits

No build, backend, API key, student account or live AI call is required. Main mission progress uses the new key `brewbyte-chapters-3-4-v1`, separate from earlier BrewByte packages. Progress remains on the current browser. It is editable practice evidence, not authenticated grading. Text and JSON exports are available; JSON import is not implemented. Clearing site data can erase progress.

The local SHA-256 explorer needs a supported secure browser context. Windows/Linux examples are inspection exercises only and do not execute commands from the site. Use synthetic output or an approved lab device; do not collect real device details in public submissions.

Run `node --test brewbyte-chapters-3-4/test.cjs` from the repository root. See `COVERAGE.md` for the concept inventory and `VALIDATION.md` for checks and limits.
