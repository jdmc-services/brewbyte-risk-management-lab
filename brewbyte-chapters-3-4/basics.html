2 · Just one formula

How long will the file take?

Files are often measured in MB (megabytes). Connection rates use Mbps (megabits per second). There are 8 bits in 1 byte.

File size in MB × 8 ÷ rate in Mbps = seconds
  1. BrewByte’s backup is 100 MB.
  2. Convert to megabits: 100 × 8 = 800 megabits.
  3. Use the upload rate: 800 ÷ 20 = 40 seconds.

This is an ideal estimate. Other traffic, protocol overhead, server limits, and connection conditions can make the real transfer take longer.

Explore further: larger files and speed labels

For this lesson, use decimal units: 1 GB = 1,000 MB and 1 Gbps = 1,000 Mbps. A 1 GB upload at 20 Mbps has an ideal time of 1,000 × 8 ÷ 20 = 400 seconds, or 6 minutes 40 seconds.

MB/s is different from Mbps. To estimate MB/s from Mbps, divide by 8. A 20 Mbps rate is 2.5 MB/s before overhead.

A local cable speed is separate from the ISP rate. A 1 Gbps Ethernet link inside the shop does not increase an Internet plan’s 20 Mbps upload rate.

Bandwidth describes capacity; throughput is the rate achieved. Latency describes delay. These ideas help explain why a “fast” connection can still feel slow.

3 · Follow a coffee order

TCP/IP: getting the menu to the customer

A customer opens BrewByte’s menu. In this simplified example, the browser uses an HTTPS connection over TCP.

IP → addressing and routing

Internet Protocol supplies addressing information. Routers use IP information to forward packets toward their destination.

TCP → reliable, ordered delivery

Transmission Control Protocol tracks data, supports retransmission when needed, and delivers an ordered byte stream to the application.

Select each step. Focus on the job being done; no port numbers or protocol layers to memorize.

1 · Find the server

The browser needs the server’s address. DNS helps resolve the fictional name orders.brewbyte.example. IP addressing and routing help packets travel to the destination.

Remember two jobs: IP helps packets get to the addressed destination. TCP supports reliable, ordered communication. TLS supplies the connection protection used by HTTPS; TCP alone does not encrypt the menu.

OPTIONAL · ABOUT 5 MINUTES

Inspect a Windows or Linux connection

Use your own or an authorized lab device. These examples inspect configuration; the page does not run commands. You can learn entirely from the sample output.

Three different checks:
Address/route commands: show configuration.
Ping: checks for replies and reports response delay; it does not measure upload/download Mbps.
Speed test: estimates current transfer performance using a test service.
Optional: understand a ping command

Start with loopback, which means this computer:

Windows: ping -n 4 127.0.0.1
Linux: ping -c 4 127.0.0.1

Both request four replies. A reply here tests the local IP stack; it does not prove that Wi-Fi, the gateway, DNS, or the Internet is working.

For a network reachability exercise, ask your device or network administrator for an approved gateway or host. Use that address instead of 127.0.0.1. No reply can mean filtering or other conditions; it does not by itself prove the destination is offline.

Some Linux installations do not include ip or ping. Use the sample output or ask your device or network administrator rather than installing tools for this lesson.

Optional: check speed without confusing the numbers
  1. Use an authorized speed-test service on an approved device.
  2. Identify the download Mbps, upload Mbps, and latency in ms.
  3. Compare the upload result with the plan’s upload rate—not its download rate.
  4. Consider other users, Wi-Fi signal, the device, and the test server before drawing conclusions.

A Windows or Linux adapter’s displayed link speed is the local connection rate, not proof of the ISP’s Internet speed. A speed test consumes data and is a measurement at that time, not a guarantee.
