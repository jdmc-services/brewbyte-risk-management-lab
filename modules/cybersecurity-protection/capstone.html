Protect BrewByte: Security Architecture Capstone

Design a defensible security program for a fictional coffee company with four stores, a small headquarters, remote workers and an AI inventory assistant.

Business context

BrewByte processes payments, maintains staff records, supports customer Wi-Fi, and depends on cloud applications. Management needs security controls that are practical, documented and measurable.

How to validate your work

  1. Define assumptions and a clearly authorized test scope.
  2. Demonstrate at least one allow rule and one deny rule with synthetic evidence.
  3. Show how you verified an identity access decision.
  4. Analyze an invented alert and distinguish observation from inference.
  5. Explain how an AI assistant is prevented from following malicious retrieved instructions.
  6. Document what the controls cannot guarantee and how you would monitor them.

Portfolio publishing checklist

Use original diagrams, fictional identities and sanitized screenshots. Never publish passwords, keys, private infrastructure details, proprietary training materials or sensitive records. Include a README with purpose, assumptions, architecture, controls, test results and limitations.
